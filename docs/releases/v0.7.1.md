# EATF v0.7.1 — malformed ML-DSA entries are rejected, not crashed on

This patch makes both verifiers return `valid: false` with the same
first-failure code for malformed ML-DSA-65 entries, with or without
`--pqc-signer-key`. In v0.7.0 and earlier they crashed on several of them, and
on some the two verifiers (TypeScript and Python, both built by Tyche
Institute) disagreed on whether to accept the package.

## Fixed

Starting from the lab's `01-valid-hybrid.aep`:

| Entry change | TypeScript in v0.7.0 | Python in v0.7.0 | v0.7.1, both |
|---|---|---|---|
| `signature_pqc.sig` is not base64 | crash, exit 2 | traceback, exit 1 | `PQC_SIGNATURE_ENCODING` |
| valid signature with one `!` inserted | crash | accepted | `PQC_SIGNATURE_ENCODING` |
| signature with a BOM or non-breaking space | accepted | traceback | `PQC_SIGNATURE_ENCODING` |
| signature missing its padding | `PQC_SIGNATURE_INVALID` | traceback | `PQC_SIGNATURE_ENCODING` |
| `pqc_public_key.pem` is an RSA key or not PEM | `PQC_VERIFY_ERROR` | traceback | `PQC_VERIFY_ERROR` |
| empty `pqc_public_key.pem` | `PQC_VERIFY_ERROR` | `PQC_PAIR_INCOMPLETE` | `PQC_VERIFY_ERROR` |
| empty pair added to a classical-only package | `PQC_VERIFY_ERROR` | accepted | `PQC_VERIFY_ERROR` |

None of these let a forged ML-DSA-65 signature, or one made by an unpinned
key, pass `--require-pqc` or `--pqc-signer-key`. The accepted cases were
lenient readings of an authentic signature, or (in Python) a classical-only
reading of an empty pair, which `--require-pqc` and a pin already rejected.
They were still cases where the two verifiers returned different verdicts
for the same package.

## Changes

- New failure code `PQC_SIGNATURE_ENCODING`, with `pqcValid: false`, when
  `signature_pqc.sig` does not decode. It mirrors `RSA_SIGNATURE_ENCODING`.
- One decoding rule for `signature_pqc.sig` in both languages: TAB, LF, VT,
  FF, CR and space may appear anywhere, and the remaining bytes must be base64
  with at most two trailing `=` and a length that is a multiple of four.
  Signatures written by `eatf-sign` are unaffected, including ones re-wrapped
  at 64 columns.
- An ML-DSA entry that exists counts as present even when it is empty, in
  both languages.
- A Python `cryptography` backend without ML-DSA support (OpenSSL older than
  3.5) reports `PQC_SUPPORT_UNAVAILABLE` instead of crashing.
- Check order: pair and policy checks, then the optional key pin
  (`PQC_VERIFY_ERROR` or `PQC_SIGNER_NOT_TRUSTED`, with `pqcValid: null`),
  then the signature encoding, then the signature.

## Not changed

Without a key pin, the two key parsers still disagree on some malformed
spellings of `pqc_public_key.pem` that only one of them can load, for example
a bare base64 key without PEM armour, which verifies only in Python. With
`--pqc-signer-key` both verifiers already parse the key by the same rules.
Aligning the unpinned path is planned for a later release.

## Verification

- 31 new TypeScript and 35 new Python tests, built from the lab packages,
  with the same cases in both. The signature cases run with and without a
  key pin.
- Conformance: 5 accepted and 8 rejected vectors in both CLIs, unchanged.
- The deterministic lab replays 42 observations with zero verdict or
  first-failure-code mismatches. Its output is byte-identical to v0.7.0.
- The decision-path experiment gives 21/21, unchanged.
- A differential run over 34,522 generated signature and key entries found no
  crash and no signature-entry disagreement between the two verifiers.

## Versions

All npm workspaces and the Python package are 0.7.1. `eatf-verify`,
`eatf-sign` and `eatf-inspect --version` report 0.7.1.
