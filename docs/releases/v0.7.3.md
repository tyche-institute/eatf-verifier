# EATF v0.7.3 — the Python verifier checks what the time-stamp signature covers

This patch fixes the RFC 3161 check in the Python verifier. The two verifiers
(TypeScript and Python, both built by Tyche Institute) now reject the same
edited time-stamp tokens.

## Fixed

The SignerInfo signature of a time-stamp token covers its signed attributes,
not the TSTInfo that carries genTime and the message imprint. The signed
attributes bind the TSTInfo only through the message-digest attribute
(RFC 5652 §5.4). Python in v0.7.2 and earlier verified the signature but did
not compare that digest with the TSTInfo. A token could therefore claim a time,
or a package, that the time-stamping authority never signed.

| `timestamp.tsr` | TypeScript in v0.7.2 | Python in v0.7.2 | v0.7.3, both |
|---|---|---|---|
| a genuine token, genTime moved by 365 days after signing | `TSA_SIGNATURE_INVALID` | accepted | `TSA_SIGNATURE_INVALID` |
| a genuine token from another package, its imprint rewritten to this package's `hash.sha256` | `TSA_SIGNATURE_INVALID` | accepted | `TSA_SIGNATURE_INVALID` |
| an imprint under SHA-512 | `TSA_IMPRINT_UNVERIFIABLE` | `TSA_IMPRINT_MISMATCH` | `TSA_IMPRINT_UNVERIFIABLE` |

Both edited tokens start from the TEST-ONLY token of
`test-vectors/valid/minimal-roundtrip`. The second is placed in
`test-vectors/valid/mcp-tools-call-valid`. Every other package entry is
unchanged, so each package still verifies in v0.7.2 Python. The SHA-512 row
is `artifacts/authority-record-v1/test-vectors/boundary/not-determinate-imprint-alg`.
Both versions reject it; only the code changes.

## Also in this release

- `docs/authority-record-v1-scope.md` explains why the root verifiers reject
  every `verify=true` package of the frozen authority-record corpus in
  `artifacts/authority-record-v1/`. Its RFC 3161 tokens are certificate-less
  placeholders that bind none of its packages. The artifact's own verifiers
  accept an imprint mismatch as advisory, and the root verifiers have not since
  v0.2.0. The root verifiers also do not implement that profile's §4.2 warrant,
  §4.3 accepting-authority and §4.5 mandate checks. The page gives the bytes, a
  58-vector table for both lines and two latent defects of the frozen line.
- `scripts/authority-record-crosscheck.py` reproduces that table. It includes a
  control run that replaces only `timestamp.tsr` with a TEST-ONLY token over
  each package's hash, and it exits 1 if any vector is unexplained.
- `docs/aep-format.md` step 9 names the message-digest comparison.

## Not changed

- `artifacts/authority-record-v1/` is unchanged and its `SHA256SUMS` verify.
  A corpus that both lines accept would need re-issued tokens and a fixed
  SignerInfo call in the artifact's TypeScript verifier. That would be a new
  artifact version.
- The TypeScript verifier is unchanged.
- The lab ZIP has the same contents as in v0.7.0, v0.7.1 and v0.7.2.

## Verification

- `lib-python/tests/test_authority_record_scope.py` pins both edited tokens,
  the root rejection of the 32 `verify=true` authority-record vectors, and the
  one-entry control swap on `valid/mandated-action`.
- The cross-check finds 0 unexplained vectors. Verdicts equal the frozen
  expectation for 26 of 58 vectors in each root verifier and for 58 of 58 in
  each artifact verifier. The two root verifiers return the same verdict and
  code on every vector.
- Conformance: 5 accepted and 8 rejected vectors in both CLIs, unchanged.
- The deterministic lab replays 42 observations with zero verdict or
  first-failure-code mismatches. The decision-path experiment gives 21/21.

## Versions

All npm workspaces and the Python package are 0.7.3. `eatf-verify`,
`eatf-sign` and `eatf-inspect --version` report 0.7.3.
