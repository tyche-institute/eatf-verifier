# EATF v0.7.0 — ML-DSA-65 signer-key pin and counted conformance

This release closes a gap in hybrid verification and makes the native-Windows
conformance run count the vectors it checks.

## Security fix: the ML-DSA-65 key was not pinned

Through v0.6.1, `--signer-key` pinned only the RSA key in `public_key.pem`. The
ML-DSA-65 key in `pqc_public_key.pem` was read from the package itself, and
nothing else in the package authenticates it. A package whose ML-DSA half was
re-made by an unrelated key over the same `canonical.bin` was accepted by both
verifiers, under `--require-pqc`, and with the RSA key pinned. `--require-pqc`
proved that an ML-DSA-65 signature existed, not whose key made it.

- `--pqc-signer-key <PEM>` (both CLIs, repeatable), `trustedPqcSignerPems`
  (TypeScript) and `trusted_pqc_signer_pems` (Python) pin the expected
  ML-DSA-65 key. Pins are RFC 9881 SPKI or legacy raw-key PEM and are compared
  on the decoded 1952-byte FIPS 204 key. A mismatch fails with the new code
  `PQC_SIGNER_NOT_TRUSTED`.
- A pin implies the required policy, so a classical-only package cannot
  bypass it.
- `--require-pqc` without `--pqc-signer-key` now prints a warning to stderr.
  Exit status and `--json` output are unchanged.

A relying party that needs post-quantum assurance should run:

```bash
eatf-verify --require-pqc --signer-key expected-rsa.pem \
  --pqc-signer-key expected-mldsa65.pem action.aep
```

## Hardening

- In v0.6.0 and v0.6.1 the ML-DSA-65 PEM parser could take cubic time on a
  crafted `pqc_public_key.pem`; 4000 spaces without an END line took 8.9 s in
  Node. Both verifiers now use a linear-time pattern that accepts the same
  text.
- Both verifiers parse ML-DSA-65 PEM text by the same rules, so a pin file
  means the same thing to both. A pin file holds exactly one key; repeat
  `--pqc-signer-key` for several.
- Both CLIs exit 2 with one stderr line when a trust file cannot be read or a
  value option is missing its value.

Three adversarial review passes, with independent refuters, found no pin
bypass before release.

## Lab

The PQC lab adds `07-foreign-mldsa-key.aep` and a third policy, `pinned`
(`--require-pqc` plus both signer keys, shipped under `keys/`). The replay
produces 42 observations: seven packages, three policies, and two verifiers
(TypeScript and Python, both built by Tyche Institute), with zero verdict or
first-failure-code mismatches. The 24 observations of v0.6.1 are unchanged,
and packages 01–06 are byte-identical. Package 07 passes `transitional` and
`required` and fails only under `pinned`, with `PQC_SIGNER_NOT_TRUSTED`.

## Conformance and experiments

- `eatf-verify-py --conformance` on native Windows had checked no vectors and
  passed since the step was added for v0.2.0. It now counts the 5 accepted and
  8 rejected vectors. Both CLIs exit 2 when no vectors are found, and CI checks
  the summary line on Linux, macOS and Windows.
- The ordering experiment exits 1 before writing anything if any of its 25
  declared packages is missing, instead of reporting on a partial corpus.

## Versions

All npm workspaces and the Python package are 0.7.0. `eatf-verify`,
`eatf-sign` and `eatf-inspect --version` now report 0.7.0.
